# @antseed/node

The runtime around buyer-core and the plugins: P2P transport and identity, discovery, metering, seller request handling and sqlite. It is the plugin host. `src/interfaces/plugin.ts` and `seller-provider.ts` define what a plugin implements, including `serviceApiProtocols`, and the node does everything else. `seller-request-handler.ts` picks a protocol for billing only and never translates; the buyer proxy (`apps/cli/src/proxy/buyer-proxy.ts`) does that. `src/payments/` re-exports the buyer's payment code from buyer-core; the seller side (`seller-payment-manager.ts`), the sqlite channel store (`channel-store.ts`) and the chain config are node's own.

| Rule | Enforced by |
| --- | --- |
| A schema change is a new numbered migration in `src/storage/migrations/<domain>/`. A shipped one is never edited. | review only; `add-migration` skill |
| Settle-on-disconnect closes at the latest amount the buyer signed. | `tests/payment-flow-integration.test.ts` (that it settles, not the amount) |
| A request the seller bills reaches its provider only if it names one service, the one billed, and the seller sets `x-antseed-service` to it. | `tests/requested-service.test.ts`, `tests/seller-billed-service.test.ts`, `e2e/tests/seller-serves-billed-service.test.ts` |

Buyer requests may name one service with `service` and/or `model`, not a separate upstream model selection. The seller refuses the top-level selectors it knows (`models`, `route`, `fallbacks`, `default_fallbacks`, `context_window_fallbacks`, `content_policy_fallbacks`, `mock_testing_fallbacks`, `model_list`, `model_group` and `deployment_id`, including case, padding and bracketed variants) before payment. This is a list of known selectors, not a guarantee: the node cannot know every field every upstream reads, so a plugin whose upstream reads others refuses or removes them itself; add a selector here when one is found. It refuses rather than silently dropping them: a buyer asking for different routing should see that this seller does not accept it, so each refusal has its own error code (`ServiceRefusal` in `src/requested-service.ts`). Nested tool/metadata fields and provider preferences that keep the same model are not model selectors. Seller-configured aliases and fallback upstreams remain the seller's responsibility; they must serve the advertised service.

A body is a form only under `multipart/form-data` and JSON under any other content type. The seller reads JSON by `JSON.parse` and hands it to the provider labelled `application/json`, whatever label the buyer sent, so no reader takes other fields from the same bytes; no top-level JSON key may appear twice, in any letter case, since parsers differ on which of a repeated key they keep and some match keys in any case.

Billing inputs (unit-price match keys, counts, duration, video options and references, prompt and speech input) must appear once and be spelled exactly, in JSON and in a form: a field that reads as one in another letter case, padded or in array form is refused. The form fields image billing prices by (`MULTIPART_PRICED_FIELDS` in `@antseed/api-adapter`: `size`, `quality`, `resolution`, `n`) must also be short unencoded text, not files or oversized fields. No other billing input is priced from a form (video and speech billing read JSON only), so in a form the others may be files or long text. Repeated media files and collection fields such as `timestamp_granularities[]` remain valid; the short-field billing reader is unchanged.
