# Features to test (not covered yet)

One folder per product feature the testbench does not cover. Each `README.md` says what to test, what the testbench lacks to drive it, and where the feature lives in the code. Sui keeps its uncovered areas the same way: a place in the tree that says what belongs there, with no code until someone writes the test.

When a feature gets its scenario, add `Scenario: <name>` to the folder's README (the scenario itself goes to `../scenarios/<name>.mjs`) and move the folder's line in the table below from planned to covered. `pnpm testbench scenarios` lists the real scenarios; this directory lists the gaps.

Most gaps need one of three enablers: a mock upstream that speaks more than chat and image generation (`lib/mock.mjs`), the real `antseed` processes (`topology.mode: 'cli'`), or the full contract stack on `--chain local`.
